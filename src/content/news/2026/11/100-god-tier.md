## เกิดอะไรขึ้น

Chris Nesbitt-Smith นักวิจัยจาก ControlPlane ใช้ AI รุ่น Claude Opus และ Sonnet ตรวจสอบโค้ดสาธารณะของ 33 องค์กรภาครัฐในอังกฤษ พบช่องโหว่ใน 2 ใน 3 ของฐานข้อมูลโค้ดทั้งหมด (จาก 349 แห่ง) โดยกรณีร้ายแรงที่สุดคือ Planning Inspectorate ที่เผลอเผยแพร่ข้อมูล Login ของ Microsoft Entra ID ลงบน GitHub ซึ่งให้สิทธิ์การอ่านและเขียนข้อมูลใน SharePoint และ OneDrive ของพนักงาน รวมถึงบันทึก HR และหลักฐานทางกฎหมาย นอกจากนี้ยังพบช่องโหว่ในระบบของกระทรวงศึกษาธิการและพอร์ทัลข้อมูลเปิดของรัฐบาลสกอตแลนด์

## ทำไมเรื่องนี้สำคัญ

เหตุการณ์นี้ชี้ให้เห็นว่านโยบายการเปิดเผยโค้ดเพื่อความโปร่งใสและการประหยัดงบประมาณของรัฐบาลอังกฤษ กลายเป็นความเสี่ยงเมื่อขาดการบำรุงรักษา (Maintenance) และการตรวจสอบความปลอดภัยพื้นฐาน โดยช่องโหว่ที่พบไม่ใช่การโจมตีที่ซับซ้อน แต่เกิดจากความผิดพลาดพื้นฐาน เช่น การลืมลบข้อมูลระบุตัวตนออกจาก Repository สาธารณะ

## ผลกระทบที่น่าจับตา

- **สำหรับสังคม:** ความเสี่ยงต่อข้อมูลส่วนบุคคลของประชาชน: ข้อมูลในระบบจัดซื้อจัดจ้างของโรงเรียน ระบบสมัครงานของครู ซึ่งประกอบด้วยเอกสารระบุตัวตนและประวัติการทำงาน ตกอยู่ในความเสี่ยงจากการถูกเข้าถึงโดยไม่ได้รับอนุญาต

- **สำหรับนักพัฒนา:** มาตรฐานการจัดการ Secret ใน Public Repository: เน้นย้ำความสำคัญของการทำ Secret Management และการตรวจสอบโค้ดก่อน Push ขึ้น Public Repo เพื่อป้องกันการหลุดของ Credentials ที่มีสิทธิ์สูง

## มุมมองของทันเทค

บทวิเคราะห์: กรณีนี้สะท้อนว่า 'Open Source' ไม่ใช่สาเหตุของปัญหา แต่เป็น 'Poor Cyber Hygiene' หรือการขาดวินัยด้านความปลอดภัย โดยเฉพาะการจัดการ Secret และการทำ Housekeeping ในกระบวนการพัฒนาซอฟต์แวร์ ผู้อ่านสามารถนำไปประยุกต์ใช้ได้โดยการติดตั้งเครื่องมือประเภท Secret Scanning (เช่น GitHub Secret Scanning) เพื่อตรวจจับ API Key หรือ Password ก่อน Commit โค้ด ทั้งนี้ ข้อมูลในบทความยังขาดรายละเอียดว่ารัฐบาลอังกฤษมีแผนปรับปรุงงบประมาณด้านการบำรุงรักษาเทคโนโลยีในระยะยาวอย่างไรเพื่อไม่ให้เกิดปัญหาซ้ำรอย

## สรุปในประโยคเดียว
